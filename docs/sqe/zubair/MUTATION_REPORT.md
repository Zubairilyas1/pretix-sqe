## 2. Custom operators (business-rule based)
Implemented as a real Cosmic Ray plug-in (`src/tests/team/zubair/mutation/sqe_mutation_operators/`, entry point
`cosmic_ray.operator_providers: sqe`), so `cosmic-ray operators` lists them and `cosmic-ray init` applies them like core operators.
Unit tests: `src/tests/team/zubair/test_custom_mutation_operators.py` (registration, documented examples, definitions not mutated).

| Operator | Business rule | What it changes | Why the core operators cannot do it |
| :--- | :--- | :--- | :--- |
| `sqe/SwapAvailabilityVerdict` | BR-1, BR-4 | replaces `Quota.AVAILABILITY_GONE / ORDERED / RESERVED / OK` by each other verdict (3 mutants per use) | core operators change operators and numbers, never one named constant into another; a suite that only checks "0 tickets left" misses a wrong *reason* (sold vs pending vs in carts) |
| `sqe/SwapOrderStatus` | BR-3 | replaces `Order.STATUS_PENDING / PAID / EXPIRED / CANCELED` by each other status (3 mutants per use) | models a state-machine mistake such as counting pending orders as paid |

Result: run 1 found **one gap with the custom operator** - L221 `<= AVAILABILITY_ORDERED` -> `<= AVAILABILITY_GONE` survived
because no test closed a quota that was sold out by *pending* orders. The new test
`test_quota_sold_out_by_pending_orders_is_closed` kills it (run 2: 30/30 and 15/15 killed).
